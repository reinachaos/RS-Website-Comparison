# RS Website QA implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Work only in the standalone clone and assigned files.

**Goal:** Deliver and upload a repeatable, conservative migration QA suite to the user-provided repository.

**Architecture:** Versioned rules and supplemental catalogs feed bounded browser/network collectors. Pure evaluators and explicit acceptance gates produce escaped evidence reports. Independent offline and browser fixtures test the checker itself.

**Tech Stack:** Node.js 22+, Playwright Test 1.63.0, pixelmatch, pngjs, GitHub Actions.

## Tasks

- [ ] Catalog: extract only corrected final findings and historical traceability, strip local paths; create curated fixed rules and supplemental inventories. Validate exact 36/344/44/5/11 counts and all rule schemas with node:test. Cover corrected empty-anchor and mailto exceptions.
- [ ] Evaluator: add failing fixture tests for each rule contract and unavailable-source behavior; implement pure rules; rerun `node --test test/rules.test.mjs`. Never encode current defects as expected passing conditions.
- [ ] Report: add failing escaping/status/partial-coverage tests; implement `src/report.mjs`; rerun `node --test test/report.test.mjs`. Every evidence link must be relative and safe.
- [ ] Collectors: write failing status, URL, extraction and bounded-download tests; implement browser capture plus anonymous HTTP; use a local fixture server for actual anchor/layout interactions.
- [ ] Runner and baselines: write failing aggregate/exit/selection/baseline-provenance tests; implement one-command fresh execution, immutable approved baseline handling and complete result output even on blocked targets.
- [ ] Integration: install pinned dependencies, run offline and real-browser fixture tests, run live smoke then full catalog, inspect generated report/screenshots. Fix checker bugs without relaxing website requirements.
- [ ] Delivery: document exact commands and limitations in Chinese and English; add manual live QA and push/PR self-test workflows; review secrets, untracked artifacts and committed content. Commit and push only this repository, then verify remote commit and workflow state where available.

Known site differences may make live QA fail. That is expected and must not be converted into a successful site-acceptance result. An operational test suite and a passing website are different outcomes.
